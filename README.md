# 斗兽棋 · 局域网对战

一个可直接在本地运行的 4×8 暗棋式斗兽棋。主机只需 Node.js 22 或更高版本，不依赖数据库，也不需要安装任何第三方包。

## 启动

macOS 可直接双击 `start.command`，也可以在本目录打开终端运行：

```bash
node server/server.mjs
```

如果习惯 npm，也可运行：

```bash
npm start
```

默认端口是 `4173`。启动后终端会同时显示本机地址和局域网地址，例如：

```text
http://localhost:4173
http://192.168.1.25:4173
```

同一 Wi‑Fi / 局域网内的手机、平板或电脑打开第二个地址即可进入。macOS 第一次运行时若询问是否允许传入连接，请选择允许。

端口被占用时可改用：

```bash
PORT=5188 node server/server.mjs
```

## 游戏流程

1. 输入昵称，创建房间、输入朋友发来的 5 位房间码，或从公开列表直接选择“加入 / 观战”。
2. 房主可在双方准备前把初始血量设为 1–16（默认 14）、选择扩展规则，也可添加一个自动就绪的 AI 玩家补位。
3. 两个玩家席位以外的用户均可观战，观战人数不设上限；双方点击“确认准备”后开局。
4. 开局随机分配红蓝阵营、先手和 32 枚暗子位置。
5. 每回合翻一枚暗子，或移动/吃子一次；30 秒未操作会自动过轮。
6. 同一棋盘排列与行动方最多出现 3 次；会造成第 4 次重复局面的移动会被禁用，必须变招。
7. 每损失一枚棋子扣 1 格血。血量归零、认输、主动离局或断线超时都会失败。

## 扩展规则集

开房间后，房主可像开关一样组合规则；有人类玩家准备后即锁定，保证双方确认的是同一套规则。当前提供：

- **足球中毒**：吃足球或中毒单位会中毒（棋子标绿并显示剩余回合），3 个后续己方回合后死亡；中毒棋子继续吃普通单位可解毒。
- **蛇**：每方一只猫替换为蛇。成功吓退时蛇保持原位，敌子沿攻击方向后退一格；退路被棋子或边界挡住时，蛇才进入目标格并吃掉它。大象不受蛇影响。

规则集会跟随历史回放和 AI 搜索。三个版本都按当前规则的剩余棋子数量、中毒倒计时和蛇的击退结果进行推演。

## 历史对局与回放

大厅的“查看历史对局”会列出这台服务器上所有已经结束的比赛。每条记录包含双方玩家、胜方、结束时间和总步数；打开后可使用播放/暂停、前后步、进度条，并在 0.3–3.0 秒之间统一调整每一步的播放间隔。

记录默认持久化到 `data/game-history.json`，服务器重启不会清除。每一步只保存当时玩家实际可见的公开棋盘，仍未翻开的棋子不会在历史文件中泄露身份。可以通过环境变量指定其他位置：

```bash
HISTORY_FILE=/path/to/history.json node server/server.mjs
```

## 高级 AI

房主可在准备前选择 V1、V2 或 V3，再点击「添加 AI 玩家」和「确认准备」。

- **V1（经典）**：完整保留原来的 SO-ISMCTS、战术模拟和 alpha-beta 终局引擎。
- **V2（概率搜索，默认）**：在 V1 的基础上加入概率机会节点搜索、战术安全复核和强化终局搜索。
- **V3（强化学习）**：用自我对弈学到的策略为合法动作打分，再模拟双方接下来的走法。比如考虑要不要翻开足球炮架后面的暗子时，它按剩余棋池估算机会和危险，不知道那枚棋子的真实身份。游戏附带[训练好的权重](./server/models/rl-v3.json)，无需联网或自行训练。

三版都只接收与真人相同的公开信息，并根据已翻开和已吃掉的棋子计算剩余棋池概率。V2 的机会节点通道只会在模拟真正执行“翻棋”时抽样该格身份，其他暗子始终保持无类型占位符。

每步最多搜索 15 秒。服务器只保留一个全局搜索池，线程总数固定为本机可用逻辑线程数的一半；只有一间 AI 房时会用满搜索池，多间 AI 房同时思考时会按短时间片动态均分。

真人回合内 AI 会提前搜索真人各种可能操作后的公开局面。真人实际落子后，命中的分支统计会注入 AI 随后的正式搜索；翻棋预判只按剩余暗子概率展开，不会偷看真实棋子。预判时间不计入 AI 自己回合，AI 仍会获得完整的 15 秒预算。

### V3 训练和棋力评估

随附模型使用 REINFORCE 策略梯度和 Adam，从零权重开始自我对弈 **2,048 局、248,917 手**，覆盖经典、仅中毒、仅蛇和两条扩展同时开启四种规则组合。训练每局上限 180 手，1,193 局在上限内分出胜负；其余局保留实际发生的血量奖励，不虚构胜负。

留出评估使用未参与训练的开局，每对开局交换红蓝方，双方各 14 血。在四种规则下合计，**不使用额外搜索**的 V3 策略对随机合法走子为 128 胜 0 负，对「有子先吃，否则先翻」为 128 胜 0 负。另一次经典规则、8 血、每步 40 毫秒的单线程短赛中，带搜索的 V3 对 V2 为 12 胜 0 负，均以血量归零结束。这 6 对开局不能代表正式 15 秒并行对局的胜率。

要复核基准成绩、或用默认种子从零重训，在项目根目录运行：

```bash
npm run ai:train -- --evaluate  # 只评估已有权重，不写文件
npm run ai:train                # 重训并替换权重；重启服务器后生效
```

实验时可用 `RL_OUTPUT` 指定另一个模型文件，`RL_SEED`、`RL_GAMES` 调整训练种子或局数。也可以在相同开局上交换阵营比较两个版本（按墙钟限时，成绩可能随机器负载而变）：

```bash
ARENA_A=v2 ARENA_B=v3 ARENA_GAMES=12 ARENA_HEALTH=8 ARENA_TIME_MS=40 ARENA_MAX_PLIES=120 npm run ai:arena
```

可在启动时缩短正式回合预算，任何配置都会被限制在 15 秒以内：

```bash
AI_TIME_MS=3000 node server/server.mjs
```

完整规则和架构决策见 [ARCHITECTURE.md](./ARCHITECTURE.md)。

## 项目结构

```text
server/                 权威服务器、房间管理、规则引擎、三个 AI 版本、WebSocket
server/models/          随附的 V3 策略权重及训练、评估记录
scripts/                离线自我对弈训练和版本对战评估
public/                 网页、样式与手绘 SVG 棋子
data/                   跨服务器重启保留的历史对局文件
tests/                  单元与联机集成测试
ARCHITECTURE.md         规则、协议和完成标准
start.command           macOS 双击启动入口
```

房间和未完成棋局保存在内存中；停止服务器会清空它们，但已经结束的历史对局会保留在磁盘。这是面向家庭/朋友局域网对战的设计，不会向外网发送游戏数据。
